# 寻找与筛选策略

仅在用户尚无候选，需要寻找思路、搜索策略或筛选框架时读取。

## 边界

- 不替用户浏览平台寻找、推荐或点名具体对标。
- 不把常见头部账号当作默认答案。
- 可以提供用户自行执行的搜索式、渠道、记录表和筛选逻辑。
- 用户随后提供候选时，切换到验证与拆解模式。

## 先定义对标规格

从上下文提取，缺失但不影响当前策略的字段标为「待定」：

| 字段 | 要回答的问题 |
| --- | --- |
| 用户阶段 | 无业务、已有业务待增长，还是只优化内容 |
| 目标进展 | 想获得流量、咨询、成交、复购，还是进入新赛道 |
| 目标用户 | 谁在什么情境下需要什么进展 |
| 产品／交付 | 已有什么产品；没有产品时想验证什么需求 |
| 对标层级 | 赛道、完整业务、账号、产品、栏目、单篇内容或局部动作 |
| 结果尺度 | 需要学习何种可观察结果，不用虚构收入目标 |
| 限制 | 时间、预算、技能、渠道、出镜、团队和风险边界 |

不要要求找到「和用户一模一样的人」。如果完整业务差异过大，允许只寻找局部动作对标。

## 生成搜索矩阵

至少从以下维度组合关键词，不必穷举：

1. **人群／身份：** 目标用户、职业、人生阶段、地域或角色；
2. **情境／痛点：** 用户正在经历的问题、焦虑、冲突或任务；
3. **期望结果：** 用户想得到的变化；
4. **产品形态：** 课程、咨询、社群、资料、店铺、服务等；
5. **商业动作：** 预约、咨询、直播、带货、复购、私域承接等；
6. **内容形态：** 图文、视频、直播、案例、教程、复盘等；
7. **长尾限定：** 年龄、预算、经验、工具、场景或细分行业。

输出 6～12 个搜索组合通常足够。每个组合都要说明它用于发现什么类型的样本，避免只给关键词堆砌。

## 用户自行执行的搜寻步骤

1. 用搜索矩阵在目标平台或搜索引擎中检索；
2. 每个组合先收集少量不同规模的样本，不只保存头部；
3. 记录账号、内容、产品入口和观察日期；
4. 先用筛选门槛淘汰明显不合适的候选；
5. 为剩余候选收集结果证据，不根据第一印象排序；
6. 选出少量候选后返回，让 Skill 进入验证与拆解模式。

如果平台有推荐流，可以建议用户通过搜索、关注公开账号和浏览相关内容改善推荐结果；不要建议批量骚扰、伪造互动或绕过平台限制。

## 筛选门槛

### 必须满足

- 与用户要推进的结果相关；
- 存在可观察的内容或业务动作；
- 至少有一类结果信号可供验证；
- 用户能够合法取得分析所需的公开材料；
- 对标层级明确。

### 优先考虑

- 用户与对标在目标人群、产品或成交路径上至少有一个关键共性；
- 不只依赖无法复制的身份、资源或渠道；
- 有近期内容和多个样本，而不是孤立爆款；
- 能看见内容到产品的承接；
- 同赛道存在正例、弱例或反例可比较。

### 排除或降级

- 只有粉丝量，没有结果证据；
- 主要优势来自用户无法合法获得的独占资源；
- 候选与用户产品、受众和场域完全错位；
- 需要私人数据才能完成关键判断；
- 只能复制具体表达，无法提炼机制。

## 停止搜索

出现以下任一情况即可停止继续扩张候选：

- 已有 3～5 个候选覆盖不同规模或不同做法，足以比较；
- 新候选不再提供新的机制或反例；
- 关键判断已经转为验证证据，而不是继续找更多账号；
- 用户的目标或产品仍然模糊，继续搜索只会扩大噪音；
- 搜索开始依赖非公开数据、侵扰式联系或绕过平台限制。
