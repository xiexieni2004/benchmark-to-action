# 从对标转化为行动

在用户已经有候选机制，但不知道如何结合自己的资源执行时读取。

## 判断用户阶段

| 阶段 | 典型表现 | 当前任务 |
| --- | --- | --- |
| 复制动作 | 只能跟着案例做，不清楚完整链条 | 还原行动链并开始执行 |
| 补齐断点 | 知道步骤，但部分环节做不了 | 找到功能等价替代 |
| 内化认知 | 能执行，但依赖固定模板 | 提炼功能、前提和失效边界 |
| 自主构建 | 能解释机制并组合方法 | 设计自己的完整路径 |
| 扩大边界 | 旧方法可用，但成长停滞 | 选择可止损的相邻挑战 |

阶段不是能力评价，只用于决定本次输出重点。

## 将动作转成机制

对每个关键动作填写：

| 对标动作 | 商业功能 | 生效前提 | 用户已有条件 | 用户缺口 | 失效边界 |
| --- | --- | --- | --- | --- | --- |

常见商业功能包括吸引注意、筛选用户、建立信任、解释价值、验证需求、促进成交、完成交付和推动复购。

如果无法说明功能，不要直接模仿该动作。

## 设计功能等价替代

替代方案可以改变形式，但必须保留功能。例如：

- 直播用于建立信任，用户不会直播时，可测试公开答疑、录屏讲解、案例拆解或小规模线上说明会；
- 高成本拍摄用于展示产品，资源不足时，可测试真实演示、前后对比、流程截图或用户可核对的样本；
- 大型社群用于持续交付，早期可先用固定频率的小组答疑或一对一试交付验证需求。

上述只是功能示例，不是默认答案。根据用户的受众、产品、能力和渠道选择。

优先选择：

- 用户现在就能开始；
- 成本和损失有上限；
- 能产生可观察反馈；
- 不依赖伪造身份或复制作品；
- 成功后可以继续扩展。

## 最小实验

实验只验证一个关键假设。至少包含：

| 字段 | 内容 |
| --- | --- |
| 假设 | 哪个机制在用户条件下可能有效 |
| 目标用户 | 谁在什么情境下参与 |
| 动作 | 用户具体做什么 |
| 独立表达 | 使用什么真实案例、材料或产品 |
| 范围 | 时间、样本量、预算或发布数量 |
| 领先指标 | 点击、回复、预约、完成等早期信号 |
| 商业指标 | 询单、成交、复购等；不可得时写未知 |
| 风险上限 | 最多投入什么、不能触碰什么 |
| 停止条件 | 何时停止、调整或补证 |
| 复盘问题 | 结果支持或推翻了哪个假设 |

不要承诺实验成功。实验的价值是减少不确定性。

## 能力边界

对已经能稳定执行旧路径的用户，可以提出位于能力边界附近的挑战：

- 一部分依赖已有能力，确保有可执行起点；
- 一部分需要新能力，带来真实学习；
- 可以拆成小步并设置止损；
- 失败不会造成不可承受损失。

不要把「走出能力圈」解释成高杠杆、无预算上限、辞去工作或其他不可逆冒险。
